# ProjectF 测试与验收方案

## 1. 测试目标

重点防止四类高风险问题：

1. 金额和汇总计算错误。
2. 跨组或跨用户越权。
3. 离线同步导致重复、覆盖或丢失数据。
4. Android 与 Windows 功能或字段不一致。

## 2. 测试分层

### 2.1 Go 单元测试

覆盖：

- 单价 × 数量。
- 含税价/不含税价枚举校验、序列化及其不改变一期金额公式的规则。
- 公司/客户小计和总金额。
- 三类销售金额汇总。
- 未付款、未收款及毛利润。
- 人民币金额大写的后端校验或共享规则。
- 权限判定。
- 单据和审批状态转换。

### 2.2 Go 集成测试

使用真实测试 MySQL 或 Testcontainers 验证：

- 数据库迁移。
- 事务回滚。
- 幂等请求。
- 乐观锁冲突。
- 组隔离。
- Refresh Token 轮换和撤销。
- 结算源单关联及快照。

### 2.3 Flutter 单元测试

覆盖：

- JSON 模型转换。
- 表单校验。
- 金额计算展示。
- 含税价/不含税价字段的 JSON 转换和必填校验。
- 日期规范化。
- 辅助填写搜索和型号按品名过滤。
- 同步队列状态转换。

### 2.4 Flutter Widget 测试

覆盖：

- Android 纵向入库/出库表单。
- Windows 宽表。
- 动态增加、删除公司、客户和产品行。
- 每条入库、出库明细均可选择并展示含税价/不含税价。
- 三种辅助填写模式。
- 权限导致的按钮显示和禁用。
- 加载、空数据、错误和冲突状态。

### 2.5 端到端测试

至少覆盖：

- 登录 → 创建入库单 → 后台查询。
- 登录 → 创建出库单 → 后台查询。
- 选择源单 → 申请结算 → 后台审批 → 业务员查看结果。
- Android 断网填单 → 恢复网络 → 同步成功。
- 主账号邀请成员并授权。
- 平台运营创建组、指定主账号并完成主账号更换。

## 3. 权限测试矩阵

每个核心接口至少测试：

- 未登录。
- 同组本人资源。
- 同组他人资源但无授权。
- 同组他人资源且有授权。
- 跨组资源。
- 主账号访问组内任意业务资源。
- 平台运营尝试直接访问租户业务资源。
- 被禁用或移出组的账号。

前端显示正确不能替代 API 越权测试。

## 4. 金额测试

边界数据包括：

- 数量为 0。
- 单价为 0。
- 小数数量和小数单价。
- 同一金额数据分别选择含税价、不含税价，验证金额公式结果不变且税价类型正确保存。
- 大金额。
- 多条明细累计。
- 删除中间行后重新编号和汇总。
- 相同请求重复提交。

验证客户端展示值、API 返回值和数据库值一致，并确保没有浮点误差。

## 5. 离线与同步测试

- 无网络创建草稿。
- 无网络连续编辑同一草稿。
- 请求发送中断网。
- 服务端已成功但客户端未收到响应，再次重试。
- 同一幂等键重复请求。
- 两台设备同时编辑同一单据。
- 同步失败后手动重试。
- 账号被移出组后仍有本地待同步数据。
- Token 过期时同步队列暂停并在重新认证后恢复。

## 6. 后台与报表测试

- 年、月筛选。
- 业务员筛选。
- 日期和业务员列显示开关。
- 付款、收款和开票筛选。
- 全部视图和单业务员视图结果一致。
- 汇总值可以从底层明细人工复算。
- 结算单利润可以从关联源单复算。

## 7. 客户端兼容测试

### Android

- 至少覆盖一个低分辨率手机和一个主流分辨率手机。
- 测试软键盘、旋转策略、长表单滚动、返回键和进程被系统回收。
- 测试权限、安装、升级和签名包。

### Windows

- Windows 10/11 64 位。
- 不同 DPI 缩放。
- 最小窗口宽度和最大化。
- 鼠标、Tab、Enter、Esc 和滚动。
- 安装、覆盖升级和卸载。
- 未签名或签名安装包的 SmartScreen 表现。

### Web

- Chrome 与 Edge 当前稳定版。
- 登录 Cookie、CORS、刷新路由、下载和缓存更新。
- 完整验证登录、入库、出库、结算、审批权限和汇总流程。
- 与 Android、Windows 对照验证字段、权限和计算结果一致。

## 8. 安全测试

- SQL 注入和非法排序字段。
- JWT 篡改、过期和错误签名。
- Refresh Token 重放。
- ID 枚举与跨组访问。
- 权限提升。
- 敏感数据进入日志。
- 暴力登录和基本限流。
- Web XSS、CSRF 和不安全 Cookie。

## 9. 发布验收门槛

发布前必须满足：

- 核心闭环端到端测试全部通过。
- 权限矩阵无高风险失败。
- 金额和汇总测试全部通过。
- Android 离线同步无已知重复或丢失问题。
- 数据库备份可以成功恢复到测试环境。
- Android Release 和 Windows 安装包在干净设备验证通过。
- Web 正式环境在 Chrome、Edge 验证通过，并完成 HTTPS、缓存更新和路由刷新检查。
- HTTPS 证书、域名和健康检查正常。
- 已知问题有明确等级、影响范围和处理结论。

## 10. 甲方验收场景

建议让甲方按照真实工作流程验收，而不是逐个按钮检查：

1. 业务员新建入库单并添加两个进项公司、多条产品，同时为每条明细选择含税价或不含税价。
2. 业务员新建出库单并选择销售金额类型及明细税价类型。
3. 断网保存 Android 草稿并恢复同步。
4. 后台按业务员和月份看到相应记录。
5. 业务员选择源单申请结算。
6. 后台审批并查看利润、付款、收款和开票状态。
7. 业务员查看审批结果。
8. 主账号默认查看组内全部数据，并授权财务子账号查看全部汇总。
9. 平台运营创建公司/组、指定主账号并完成一次主账号更换，确认组内不存在第二个有效主账号。
10. 在 Web 端重复核心业务流程，并确认三端读取到同一份服务器数据。

## 11. 待甲方确认事项

以下事项尚未冻结，未确认前不能作为最终验收承诺：

| 事项 | 需要确认的问题 | 一期建议 |
|---|---|---|
| 结算审批人 | 主账号、财务还是固定负责人审批 | 主账号默认可审批，其他成员按权限授权 |
| 驳回重提 | 修改原申请还是复制新申请 | 保留审批历史，在原申请新版本上重提 |
| 已结算源单 | 审批通过后是否允许修改 | 锁定源单，通过更正流程处理 |
| 分次资金记录 | 是否允许多次付款、收款和开票 | 数据模型按多条明细设计 |
| 毛利润 | 是否扣除税费、运费等成本 | 暂按销售合计减进项合计，并明确展示口径 |
| 结算分组 | 多张源单按客户、公司还是申请批次生成 | 一次申请生成一张，其他限制待确认 |
| 消息提醒 | 触发事件、时间、对象和渠道 | 先实现站内审批结果消息 |
| Windows 离线 | 是否要求完整断网录入同步 | 在线优先并保存本地草稿 |
| 单号规则 | 用户填写还是系统生成 | 后端生成正式单号，离线使用临时编号 |
| 客户新增 | 文档中“客户辅助填写”和“无客户添加”存在冲突 | 主账号或获授权的字典管理人员维护，普通用户按规则申请保存 |
| 第三方通信 | 指短信、企业微信、微信登录还是其他接口 | 未确认前只做站内消息 |
| 打印导出 | 是否要求 Excel、PDF 和正式打印模板 | 未确认前不纳入核心验收 |
| 高级品名统计 | `后台PC.xlsx` 的待开发功能是否属于一期 | 不纳入一期 |

每项获得甲方结论后，应同步修改 `需求.md` 和对应测试用例，并从本表移除。
