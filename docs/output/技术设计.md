# CBizDocsManager 一期技术架构

## 1. 架构结论

一期采用“Flutter 多端客户端 + Go 单体后端 + MySQL/RDS”的结构。

```text
Android App ─────┐
Windows Client ──┼─ HTTPS ─ Caddy/Nginx ─ Go API ─ MySQL/RDS
Flutter Web ─────┘                         │
                                          ├─ Redis（可选）
                                          ├─ 安装包/对象存储
                                          └─ 日志与监控
```

Android、Windows 和 Web 均为正式客户端目标。该结构适合约 100 名用户，减少单人开发时的重复代码和运维负担。

## 2. 客户端技术栈

### 2.1 基础技术

- Dart。
- Flutter 与 Material 3。
- Riverpod：状态管理与依赖注入。
- GoRouter：页面导航和权限路由。
- Dio：HTTP 请求、JWT 拦截器和统一错误处理。
- Freezed/JSON Serializable：不可变模型和 JSON 转换，是否引入在原型阶段确认。
- Drift + SQLite：Android 本地草稿、缓存和同步队列。
- flutter_secure_storage：安全保存刷新凭据。

### 2.2 共享与差异

共享代码包括：

- API 数据模型。
- 认证与权限逻辑。
- 金额计算和表单校验。
- 入库、出库、结算和汇总状态管理。
- 辅助填写匹配逻辑。
- 大部分基础表单组件。

平台差异包括：

- Android：纵向表单、本地数据库、离线同步、APK/AAB 更新。
- Windows：宽表、键盘焦点、窗口管理、安装包和代码签名。
- Web：Cookie/CORS、浏览器缓存、路由刷新和静态部署。

## 4. 后端技术栈

- Go。
- Gin：HTTP 路由和中间件。
- GORM：数据访问；复杂汇总允许使用明确的原生 SQL。
- MySQL 8：主数据存储。
- Viper：配置加载。
- Zap：结构化日志。
- go-playground/validator：请求参数校验。
- golang-jwt/jwt/v5：JWT 签发与校验。
- shopspring/decimal 或整数分：金额计算。
- Redis：可选缓存、限流或短期状态；不是核心数据源。
- 数据库迁移工具：golang-migrate、Atlas 等择一。
- OpenAPI：维护接口契约并辅助生成客户端模型。

## 6. API 设计原则

- REST 风格 JSON API。
- API 统一使用 `/api/v1` 前缀。
- 列表接口分页，并提供稳定排序。
- 写请求支持 `Idempotency-Key`。
- 资源更新携带版本号，执行乐观锁。
- 错误响应包含稳定业务码、用户提示和字段错误。
- 不在 URL 或日志中传递令牌和敏感财务信息。

示例资源：

```text
/api/v1/auth/*
/api/v1/groups/*
/api/v1/members/*
/api/v1/permissions/*
/api/v1/dictionaries/*
/api/v1/inbound-documents/*
/api/v1/outbound-documents/*
/api/v1/settlements/*
/api/v1/approvals/*
/api/v1/reports/*
/api/v1/notifications/*
```

## 7. JWT 与会话

- Access JWT 短时有效。
- Refresh Token 每次刷新后轮换。
- Refresh Token 仅保存哈希到 MySQL。
- Android/Windows 将刷新凭据放入系统安全存储。
- Web 建议将刷新凭据放入 `HttpOnly + Secure + SameSite` Cookie。
- JWT 可以包含用户 ID、组 ID、会话 ID，但不能把长期不变的完整权限写死在长效令牌里。

## 8. 数据与金额

- MySQL 金额使用 `DECIMAL`，或在业务层统一使用整数分。
- Go 和 Dart 禁止用二进制浮点直接累计金额。
- 一期金额公式为单价 × 数量。
- 入库和出库商品明细包含 `price_tax_mode`，稳定值为 `tax_included`、`tax_excluded`；该字段一期仅用于记录与展示，不改变金额公式。
- 重量独立保存。
- 日期在数据库保存明确的日期类型；时间戳统一保存 UTC，客户端按本地时区展示。

## 9. 同步架构

Android 使用 Local-First 草稿模式：

```text
UI → 本地 Repository → SQLite
                     └→ Outbox → API → MySQL
```

- 本地生成客户端请求 ID。
- 网络恢复时顺序同步待处理操作。
- 后端使用幂等键防止重复创建。
- 服务端版本变化时返回冲突。
- 用户明确选择重新加载或另存，不执行静默覆盖。

Windows 一期可先采用在线优先并保留本地草稿，是否提供完整离线同步在需求冻结时确认。

## 11. 可用性策略

- Redis 故障时回退 MySQL。
- MySQL 使用托管实例、自动备份和恢复演练。
- 写操作使用事务、幂等键和版本控制。
- 服务提供 `/health/live` 与 `/health/ready`。
- 日志包含请求 ID，但隐藏令牌和敏感数据。
- 一期优先保证可恢复性，不引入 Kubernetes 和复杂集群。

## 12. 权限设计摘要

### 12.1 身份关系

```text
平台运营人员
└─ 公司/组
   ├─ 主账号（唯一，组内管理员）
   └─ 子账号（业务员、财务等）
```

- 每个组有且只有一个主账号，主账号即组内管理员，默认拥有组内全部业务与管理权限。
- 平台运营人员负责创建、停用组以及指定或更换主账号，不作为组内业务成员，也不默认拥有租户业务数据权限。
- 主账号负责成员邀请、停用、移除和授权，不能将其他成员设置为第二个主账号。
- 子账号默认只能查看、编辑本人创建的单据。
- 主账号可以向子账号额外授予查看他人单据、编辑他人单据、汇总查看和账号管理权限。
- 财务人员是获得财务权限的子账号，不是默认超级用户。

### 12.2 权限判定维度

每个后端请求同时校验：

1. 当前登录会话。
2. 当前公司/组。
3. 资源是否属于该组。
4. 功能权限，例如查看、编辑、审批或授权。
5. 数据范围：本人、明确分配或组内全部。
6. 单据当前业务状态。

前端隐藏按钮仅改善体验，不能代替后端权限校验。

### 12.3 默认权限矩阵

| 能力 | 主账号（组内管理员） | 普通子账号 |
|---|---:|---:|
| 查看组内全部业务 | 是 | 按授权 |
| 邀请、停用和移除组员 | 是 | 否 |
| 配置子账号权限 | 是 | 否 |
| 创建业务单据 | 是 | 是 |
| 查看/编辑本人单据 | 是 | 是 |
| 查看/编辑他人单据 | 是 | 按授权 |
| 查看汇总 | 是 | 按授权 |
| 审批结算 | 是 | 按授权 |

## 13. 数据模型摘要

```text
Group
├─ Membership ─ User
├─ DictionaryEntry
├─ InboundDocument
│  └─ InboundCompanyGroup
│     └─ InboundItem
├─ OutboundDocument
│  └─ OutboundCustomerGroup
│     └─ OutboundItem
├─ Settlement
│  ├─ SettlementSource
│  └─ ApprovalRecord
├─ Payment / Receipt / InvoiceRecord
├─ Notification
└─ AuditLog
```

### 13.1 核心约束

- 所有公司业务表包含 `group_id`，查询必须带组范围。
- 每个组只能存在一个有效主账号成员关系；主账号变更必须由平台运营执行并写入审计日志。
- 入库单通过公司分组承载多家公司、多条产品。
- 出库单通过客户分组承载客户及产品明细。
- 型号关联品名，辅助数据被停用后仍保留历史快照。
- 入库、出库明细包含 `price_tax_mode`，只允许 `tax_included`、`tax_excluded`。
- 一期单条金额为单价 × 数量，税价类型不改变计算公式，重量独立保存。
- 金额使用 MySQL `DECIMAL` 或整数分，禁止直接使用二进制浮点累计。
- 重要资源包含 `version` 字段实现乐观锁。
- 结算单通过 `settlement_sources` 关联源入库、出库单，并保存生成时快照。
- 付款、收款和发票按明细建模，以支持后续分次处理。
- 审计日志只追加，普通业务用户不能修改。

### 13.2 关键表

- `users`、`groups`、`memberships`、`membership_permissions`。
- `dictionary_entries`，包含类型、父级、规范化值和停用状态。
- `inbound_documents`、`inbound_company_groups`、`inbound_items`。
- `outbound_documents`、`outbound_customer_groups`、`outbound_items`。
- `settlements`、`settlement_sources`、`approval_records`。
- `payment_records`、`receipt_records`、`invoice_records`。
- `refresh_sessions`、`idempotency_records`、`notifications`、`audit_logs`。

最终字段和索引应在待确认业务规则冻结后，通过数据库迁移脚本定义。
