# CBizDocsManager 一期产品需求说明

> 文档状态：需求基线草案，等待项目负责人审阅  
> 更新日期：2026-07-20  
> 适用范围：Android 客户端、Windows 客户端、Web 端、后台 PC 端及 Go 后端

## 1. 需求依据与优先级

需求冲突时按以下优先级处理：

1. 项目负责人在沟通中明确确认的决策。
2. `docs/甲方/要求总述.docx`。
3. `docs/甲方/业务员手机端适配1.xlsx`、`docs/甲方/业务员PC端适配1.xlsx`、`docs/甲方/后台PC.xlsx`。
4. `docs/甲方/要求.docx`、`docs/甲方/演示示例1.xlsx` 和历史截图。

最新文档已明确：一期自动金额按“单价 × 数量”计算；重量为业务记录字段，不参与一期自动金额计算。每条商品明细还必须选择“含税价”或“不含税价”，该选择用于业务记录与展示，不改变一期金额公式。

## 2. 产品目标

面向钢材批发市场的小型公司，提供业务员入库、出库登记，结算单申请与审批，付款、收款、开票跟踪，以及公司级数据汇总能力。

产品需要减少业务员重复录入，降低财务整理数据和管理人员审核单据的工作量，并保证同一组内的数据隔离、权限控制和操作可追溯。

## 3. 一期交付范围

### 3.1 正式交付

- Android 客户端：主要交付物，支持业务填写、历史查看、结算申请、汇总管理及离线草稿。
- Windows 10/11 64 位客户端：与 Android 具有相同的核心业务功能，采用桌面宽表布局。
- Flutter Web：与 Android、Windows 共享业务代码，提供同等核心业务功能，采用浏览器桌面布局并在线使用。
- 后台 PC 端：用于公司数据汇总、结算单生成与审批、付款/收款/开票查询、提醒及统计。
- Go 后端服务：统一为所有客户端提供认证、权限、业务、同步和统计 API。

### 3.2 三端一致性

- Android、Windows 和 Web 均属于一期正式交付与验收范围。
- 三端共享数据模型、权限、计算规则和 API，不允许出现同一账号在不同端获得不同业务权限的情况。
- Android 重点保证移动填写和离线草稿；Windows、Web 重点保证桌面宽表和汇总管理体验。

### 3.3 用户规模

- 系统整体预计约 100 名用户。
- 单个公司/组初期通常不超过 10 名成员。

## 4. 用户、组织与权限

### 4.1 组织模型

- 一个公司对应一个数据隔离组，也称存储单元。
- 每个组包含一个主账号和若干子账号。
- 所有业务数据必须归属某个组，后端查询必须强制附带组范围。

### 4.2 身份类型

#### 平台运营人员

- 使用平台运营入口管理公司/组。
- 创建、停用公司/组，并为组指定或更换主账号。
- 查看必要的系统运行与审计信息。
- 不作为组内业务成员，不默认拥有查看或操作租户业务数据的权限。

#### 主账号（组内管理员）

- 每个组有且只有一个主账号，主账号即该组的组内管理员。
- 默认拥有所在组内全部业务与管理权限。
- 邀请、查看、停用和移除组员。
- 配置子账号的查看、编辑、汇总及账号管理权限。

#### 普通子账号

- 默认只能查看和编辑自己创建的单据。
- 可由主账号额外授予查看他人单据、编辑他人单据、汇总查看或账号管理等权限。
- 业务员和财务人员均属于子账号；财务人员通过授权获得查看全部单据、汇总数据等能力。

### 4.3 权限原则

- 前端仅负责展示权限结果，最终权限必须由后端校验。
- 权限至少同时考虑：组范围、资源类型、资源归属人和操作类型。
- 创建、修改、删除、恢复、提交、审批、授权和主账号变更必须记录审计日志。

## 5. 核心业务流程

```text
业务员填写入库单/出库单
          ↓
保存草稿或提交到后台
          ↓
业务员选择需要关联的入库单和出库单
          ↓
申请生成销售结算单
          ↓
后台自动汇总并生成结算单
          ↓
有审批权限的后台人员审批
          ↓
业务员查看通过/驳回状态及历史记录
          ↓
后台继续跟踪付款、收款、开票和利润
```

## 6. 账户与认证功能

### FR-AUTH-01 注册与登录

- 支持账号注册和登录。
- 使用短时效 Access JWT 与可撤销的 Refresh Token。
- Android/Windows 使用系统安全存储保存刷新凭据。
- 正式环境 API 必须使用 HTTPS。

### FR-AUTH-02 会话管理

- 支持刷新登录状态、主动退出和服务端撤销会话。
- 账号被删除、禁用或移出组后，不得继续访问原组数据。

### FR-AUTH-03 成员管理

- 主账号可以邀请、查看、停用和移除组员。
- 主账号可以配置子账号权限，但不能将其他成员设置为第二个主账号。
- 平台运营人员可以创建、停用组，并指定或更换该组唯一的主账号。

## 7. 辅助填写系统

### FR-ASSIST-01 填写状态与管理状态

辅助填写功能分为填写状态和管理状态：

- 填写状态：用于业务录入。
- 管理状态：用于新增、修改和删除辅助填写数据。

### FR-ASSIST-02 三种填写模式

#### 纯净填写模式

- 不进行联想或推荐。
- 所有内容填写完成后，询问是否将新内容保存至辅助填写系统。

#### 联想填写模式

- 允许用户输入。
- 根据输入内容显示匹配选项。
- 用户点击选项完成确认。

#### 辅助填写模式

- 不允许自由输入。
- 用户只能从已有选项中滑动或选择并确认。

### FR-ASSIST-03 辅助数据范围

辅助填写至少覆盖：

- 进项公司名称。
- 客户及联系电话。
- 品名。
- 型号。
- 单位。
- 出货单位。

### FR-ASSIST-04 型号归类

- 型号必须按品名归集。
- 用户选择或输入品名后，只展示该品名下的型号，不展示全部型号。

### FR-ASSIST-05 日期规范化

- 用户可输入由空格分隔的日期，例如 `2026 3 14`。
- 系统统一转换为标准日期保存，界面显示为 `2026-03-14` 或统一确认的展示格式。

## 8. 产品入库功能

### FR-IN-01 入库单基本信息

入库单包含：

- 进项公司名称。
- 业务员。
- 日期。
- 单号。

### FR-IN-02 入库产品明细

每条产品明细包含：

- 序号。
- 产品名称/品名。
- 规格型号。
- 单位。
- 数量。
- 重量。
- 单价。
- 单价类型：含税价或不含税价。
- 金额。
- 备注。

单价类型在界面显示为“含税价”“不含税价”，API 和数据库使用稳定代码 `tax_included`、`tax_excluded`。

### FR-IN-03 动态公司与明细

- 同一进项公司可以添加多条产品明细。
- 一张录入页面可以继续添加其他进项公司的产品。
- 明细序号自动连续生成。
- 删除或新增明细后，总金额区域和页面结构自动调整。
- Windows 客户端默认展示 5 行明细，但可以继续添加。

### FR-IN-04 自动计算

- 单条金额 = 单价 × 数量。
- 含税价/不含税价只作为明细业务属性保存，不改变一期自动金额计算公式。
- 公司小计为该公司全部明细金额之和。
- 入库单总金额为全部公司小计之和。
- Windows 客户端自动生成总金额人民币大写，例如 `RMB壹拾肆万陆仟玖佰捌拾贰元叁角叁分`。

### FR-IN-05 付款与开票

- 记录付款情况，包括已付款、未付款和未付款金额。
- 记录是否开发票及后续开票状态。
- 后台可以统计未付款总额和未开票记录。

## 9. 产品出库功能

### FR-OUT-01 出库单基本信息

出库单包含：

- 客户。
- 联系电话。
- 业务员。
- 交易日期。
- 出货单位。
- 日期。
- 单号。

### FR-OUT-02 销售金额类型

销售金额需要选择类型：

- `Y-1`：增值税专用发票销售金额。
- `y-N`：增值税普通发票销售金额。
- `N`：不开票销售金额。

后续 UI 应将上述内部标识转换为清晰的中文选项，数据库保留稳定代码值。

### FR-OUT-03 出库产品明细

每条产品明细包含：

- 序号。
- 产品名称/品名。
- 规格型号。
- 单位。
- 数量。
- 重量。
- 单价。
- 单价类型：含税价或不含税价。
- 金额。
- 备注。

单价类型与入库明细使用相同的稳定代码 `tax_included`、`tax_excluded`。

### FR-OUT-04 动态客户产品明细

- 同一客户可以添加多条产品明细。
- 明细序号自动生成。
- 新增或删除产品后，表格与总金额区域自动调整。
- Windows 客户端默认展示 5 行明细。

### FR-OUT-05 自动计算与收款

- 单条金额 = 单价 × 数量。
- 含税价/不含税价只作为明细业务属性保存，不改变一期自动金额计算公式。
- 自动计算客户小计及出库单总金额。
- Windows 客户端自动生成金额人民币大写。
- 记录客户收款情况和未收款金额。

### FR-OUT-06 收款方式

收款记录支持：

- 转账，并可备注微信或支付宝。
- 对私卡，并记录卡尾号。
- 对公账户。

## 10. 单据历史与结算申请

### FR-DOC-01 历史记录

- 业务员可以查看自己权限范围内的历史入库单、出库单和结算单。
- 支持按月份回顾本月单据和查看汇总结果。
- 在权限和业务状态允许时修改历史单据。

### FR-DOC-02 结算单申请

- 业务员可以选择一张或多张已录入的入库单、出库单。
- 提交生成结算单申请。
- 后台根据被选单据自动汇总形成销售结算单。
- 必须保留结算单与源入库单、出库单之间的关联关系。

### FR-DOC-03 审批状态

结算单至少包含：

- 待审批。
- 审批通过。
- 审批驳回。

业务员可以查看审批结果。驳回时应记录原因，具体修改和重新提交规则在审批流程确认后冻结。

## 11. 后台 PC 功能

### FR-BACK-01 数据汇总

- 汇总所有业务员上传的入库、出库数据。
- 支持按年份、月份和业务员筛选。
- 支持全部数据视图和按业务员视图。
- 查看时可以选择是否展示日期和业务员字段。

### FR-BACK-02 入库统计

- 统计金额总计。
- 统计未付款总计。
- 查询付款情况和开票状态。
- 支持进项公司、品名、型号等字段查询。

### FR-BACK-03 出库统计

- 分别统计 `Y-1`、`y-N`、`N` 三类销售金额。
- 统计未收款总计。
- 查询收款情况。
- 支持客户、品名、型号等字段查询。

### FR-BACK-04 结算单生成与审批

- 根据业务员选择的源入库单和出库单自动生成结算单。
- 结算单展示进项合计、销售合计和毛利润。
- 有审批权限的人员可以审批通过或驳回。
- 审批行为必须记录操作人、时间、结果和备注。

### FR-BACK-05 公司/业务员总结算

- 支持自动生成公司维度总结算单。
- 支持自动生成业务员维度总结算单。
- 支持查看业务员利润统计。

### FR-BACK-06 提醒与消息

- 系统支持提醒和消息提示。
- 一期至少需要为结算审批结果、未付款、未收款或未开票事项预留消息模型。
- 具体提醒触发时间、接收人和通知渠道在后续需求确认中冻结。

## 12. Android、Windows 与 Web 适配

### 12.1 Android

- 使用纵向分段或卡片式表单，不直接缩小桌面 Excel 宽表。
- 支持动态增加公司、客户和产品明细。
- 支持本地草稿和离线编辑。
- 网络恢复后支持手动或自动同步。
- 清晰展示未同步、同步中、同步失败和已同步状态。

### 12.2 Windows

- 面向 Windows 10/11 64 位。
- 使用桌面宽表布局。
- 支持鼠标、键盘、Tab 焦点切换和窗口缩放。
- 提供安装包、版本号、卸载信息和更新检查能力。

### 12.3 Web

- 复用桌面布局和业务逻辑。
- 使用 HTTPS 部署。
- 单独处理浏览器登录安全、CORS、路由刷新和缓存更新。
- 与 Android、Windows 一同作为一期正式交付和验收平台。
- 核心功能、字段、权限和计算结果必须与其他两端保持一致。

## 13. 数据同步与一致性

- Android 本地草稿先写入 SQLite，再进入待同步队列。
- 每次创建或修改请求携带幂等键。
- 单据使用版本号进行乐观并发控制。
- 服务器版本已变化时，客户端不得静默覆盖，应提示冲突并重新加载或另存草稿。
- Redis 仅作为可选缓存或加速层；Redis 不可用时，核心业务回退 MySQL。

## 14. 非功能需求

### 14.1 安全

- 正式 API 使用 HTTPS。
- 密码使用安全哈希保存。
- JWT 不保存敏感业务内容。
- 每个业务查询在后端执行组隔离和权限校验。
- 日志不得记录密码、完整令牌和敏感银行卡信息。

### 14.2 可用性

- MySQL 建议采用带自动备份的托管 RDS。
- 服务提供存活和就绪检查。
- 核心写操作具备幂等和事务保护。
- 制定数据库备份、恢复和故障处理流程。

### 14.3 性能

- 按约 100 名用户设计，优先使用可维护的单体架构。
- 列表接口必须分页。
- 常用筛选字段建立索引。
- 汇总查询避免一次加载全部历史明细。

### 14.4 可审计性

- 记录账号、权限、单据和审批关键操作。
- 审计日志应包含操作者、组、目标资源、动作、时间和必要的变更摘要。

## 15. 一期暂不包含

- 用户自行设计任意表单的可视化表单设计器。
- iOS 客户端。
- Kubernetes、微服务拆分和消息队列。
- Windows 常驻后台服务。
- 表格中标注“品名统计（待开发）”的高级统计功能，除非甲方后续明确纳入一期。
- 复杂多级审批流；一期先实现单级结算审批。

## 16. 验收摘要

一期至少应完成以下闭环：

1. 账号登录并进入正确的公司/组。
2. 业务员在 Android 和 Windows 创建入库单、出库单。
3. 自动计算金额、总额和 Windows 金额大写。
4. 使用三种辅助填写模式完成字段录入。
5. Android 断网保存草稿，联网后成功同步且不重复创建。
6. 业务员选择源单据申请结算。
7. 后台生成结算单并完成审批。
8. 业务员查看审批结果。
9. 后台按年月和业务员查看入库、出库、付款、收款、开票及利润数据。
10. 权限越权请求被后端拒绝，关键操作可从审计日志追溯。
11. Web 端完成登录、入库、出库、结算申请、审批权限内操作和汇总查询，并与 Android、Windows 数据一致。
