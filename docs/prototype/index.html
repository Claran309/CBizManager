01 · 登录

登录成功后后端返回 must_change_password；为 true 时客户端强制跳转改密页，改密前所有业务写接口都会被后端拦截。

登录表单

POST /api/v1/auth/login
登录失败统一返回 AUTH_INVALID_CREDENTIALS，不区分「账号不存在」与「密码错误」，避免账号枚举。

角色与落地首页

账号类型登录后首页
platform_admin平台治理 · 公司/组列表
group_owner业务首页 + 组内管理全部入口
member业务首页，入口按 permission_codes 渲染
平台运营人员 不是 组内成员，默认不拥有任何租户业务数据的查看权。
邀请码明文只在「签发」与「查看」两次响应里出现，其余时间库中只有 AES-GCM 密文与校验哈希。

后端拦截规则

接口改密前行为
/auth/me放行 需返回 must_change_password 供前端判断
/auth/password放行 唯一可调用的写接口
/groups/**、/platform/**、/dictionaries/**拦截 返回 AUTH_PASSWORD_CHANGE_REQUIRED
后续业务接口（入库 / 出库 / 结算）拦截 同上
这层拦截同时落在路由中间件与服务层：即使绕过路由，服务层也会再校验一次 principal.MustChangePassword。

业务状态 vs 同步状态

两个维度互不替代：业务状态由服务端业务流转决定；同步状态只描述本机草稿是否已成功上送。
维度取值归属
业务状态（单据）草稿 / 已提交入库、出库单
业务状态（结算）待审批 / 审批通过 / 审批驳回结算单
同步状态本地草稿 / 待同步 / 同步中 / 同步失败 / 已同步 / 版本冲突本机队列
选择实时联动：右侧合计随勾选变化，让业务员在提交前就能看到进项、销售与毛利润三个数。提交后必须保留结算单与源单据的关联关系。

结算单与源单据的关系

勾选源单据→ 生成结算单（待审批）→ 写入 settlement_sources→ 保存生成时快照
要点做法
关联关系每张源单据在 settlement_sources 存一行，记录类型与 ID
金额快照生成时把进项 / 销售 / 毛利写入结算单本体，源单据后续被改不影响已生成结算单
重复结算同一源单据不允许被两张有效结算单同时引用（服务端校验）
状态机待审批 → 审批通过 / 审批驳回（驳回必填原因）
宽表与移动端共用同一套数据模型与校验规则：字段、税价类型、金额公式、合计口径必须完全一致，只差布局。

辅助填写

项目规则
覆盖范围进项公司、客户及电话、品名、型号、单位、出货单位
型号归属型号必须挂在品名下，候选只展示该品名的型号
三种模式纯净（不联想）/ 联想（输入即匹配）/ 辅助（只能选，禁自由输入）
停用条目不再出现在候选，但历史单据保留文本快照
日期输入空格分隔也可识别，如 2026 3 14 → 2026-03-14

权限与审计

项目规则
判定维度会话 → 组范围 → 资源归属 → 功能权限 → 数据范围 → 单据状态
前端角色只隐藏入口，不承担鉴权
审计动作创建、修改、删除、恢复、提交、审批、授权、主账号变更
审计字段操作者、组、目标资源、动作、时间、变更摘要
审计约束只追加，普通业务用户不能修改或删除
日志脱敏不记录密码、完整令牌、银行卡完整卡号
