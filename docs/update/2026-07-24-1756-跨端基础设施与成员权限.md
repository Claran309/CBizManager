# Change Note: 跨端基础设施与成员权限

## 1. What Changed

这次交付完成了不依赖正式原型图的纵向基础闭环。

- Go 后端新增 Web Cookie 认证、成员生命周期、权限目录与完整替换、六类辅助字典，以及对应路由和真实 MySQL 集成测试。
- Flutter 新增跨端网络层、原生安全存储与 Web Cookie 认证、401 单飞刷新、Riverpod 认证状态、GoRouter 守卫、Drift 离线库、Outbox、成员和字典 Repository/Controller。
- Android/Windows 支持按用户和组隔离的离线缓存；Web 首期明确只走远端，不初始化业务离线数据库。
- README 增加可以直接执行的开发、测试和三平台构建命令。

这是功能、配置、数据库、测试、生成代码和运行文档的组合变更。当前没有实现正式登录页、成员管理页、字典管理页或业务单据页。

## 2. Why This Change Was Needed

原型图未到不等于项目只能停住。认证、租户隔离、权限、网络错误、缓存和同步规则属于 UI 下面的稳定边界，先完成这些边界，正式页面到达后只需组合 Controller 状态和动作。

这里的关键取舍是把原生与 Web 的凭据策略分开。原生应用没有浏览器 Cookie 安全模型，所以 Refresh Token 放系统安全存储；Web 如果把 Refresh Token 暴露给 JavaScript，会扩大 XSS 后的凭据泄漏范围，因此改用 `HttpOnly` Cookie，再用双提交 CSRF 防止跨站请求。

离线也没有被简单理解成“失败就吞掉错误”。只有真实网络失败可以读缓存；409 版本冲突、403 无权限等业务错误必须呈现给上层，否则用户会看到旧数据并误以为写入成功。

## 4. Core Flow After The Change

```text
Flutter Widget（未来正式 UI）
  -> Riverpod Controller
  -> Repository
     -> Dio Remote Data Source
        -> Go Gin Handler
        -> Service / Authorization
        -> GORM Repository
        -> MySQL
     -> 网络失败时读取 Drift（仅 Android/Windows 查询）
```

认证刷新流程：

```text
多个请求同时收到 401
  -> 共用同一个 refresh Future
  -> 原生读取 Secure Storage / Web 携带 HttpOnly Cookie + CSRF
  -> 刷新成功后替换 Bearer 并各自重试一次
  -> 刷新失败后只清理一次会话
  -> AuthController 变为 unauthenticated
  -> GoRouter 回到登录路由
```

## 5. Key Code Concepts

### 单飞刷新

“单飞”表示同一时刻只允许一个刷新请求在飞。若 10 个 API 同时因 Access Token 过期返回 401，它们等待同一个刷新 Future，而不是生成 10 组轮换请求。Refresh Token 是一次性轮换的，不做单飞会让后发刷新把先发刷新刚生成的会话判成重放。

### Riverpod 与 GoRouter

Riverpod 的 `AuthController` 是认证事实源，GoRouter 只读取状态决定重定向。成员和字典 Controller 同样负责 `items/isLoading/isWriting/failure`，Widget 不保存第二份业务状态。加载使用请求代号丢弃旧响应，写操作串行，避免慢请求覆盖新状态。

### Drift Scope

本地表不是只用资源 ID 做主键，而是把 `userId/groupId` 放入 scope。相同的成员 ID 或字典 ID 即使出现在另一个账号会话中，也不能读到前一会话缓存。这相当于在客户端重复落实一次后端租户边界。

### Outbox 状态机

Outbox 保存未来可重放的离线写操作。合法路径是 `pending -> syncing`，随后进入 `succeeded`、`retryable_failed`、`conflict` 或 `permanently_failed`；只有 `retryable_failed` 可以回到 `pending`。当前成员状态、授权和字典管理写入没有进入 Outbox，因为它们依赖实时权限和版本，离线排队可能在稍后错误覆盖管理员操作。

### 乐观锁

成员、权限和字典写请求都提交当前 `version`。数据库只更新版本匹配的行，成功后版本加一；不匹配返回 409。它避免两个管理员打开同一数据后，后保存的人无提示覆盖先保存的人。

## 6. Important Implementation Details

- 受保护请求不会只相信 JWT：后端重新检查用户、组和成员是否仍为 active，所以停用立即生效。
- 普通成员即使有 `member.manage` 也不能给别人授权；完整替换权限仍是 owner 的固有职责。
- 字典只在无筛选的单 kind 在线查询成功后覆盖该 kind 完整快照；筛选查询网络失败时从完整快照本地过滤，避免用查询子集破坏缓存。
- 成员和字典远端列表会根据 `pagination.total` 拉完所有页面，再替换完整缓存，避免只缓存前 100 条。
- 远端 2xx 若字段畸形会转成 `ServerFailure`，不会让 `FormatException` 绕过 Controller 的 failure 状态。
- Web `withCredentials` 只解决 Cookie 携带问题，刷新和退出仍必须发送与 CSRF Cookie 相同的 `X-CSRF-Token`。
- Drift Web 连接当前故意抛出 `UnsupportedError`。这不是遗漏，而是首期不承诺 Web 离线能力。
- 成员和字典 Repository Provider 尚未在全局 bootstrap 固定装配；它们必须在认证完成、已知 `userId/groupId` 后按会话创建，并在账号或组切换时销毁。

本次已成功执行以下命令：

```powershell
Set-Location backend
go test ./... -count=1
go vet ./...
go build -o "$env:TEMP\cbizdocsmanager-api.exe" ./cmd/api

Set-Location ../client
dart run build_runner build
flutter analyze
flutter test
flutter build apk --debug
flutter build web
```

Windows 构建也已执行：

```powershell
flutter build windows --debug
```

本机未启用 Windows 开发者模式，Flutter 因插件无法创建符号链接而在编译前退出。这个结果属于环境前置条件未满足，不代表 Windows 产物已验证；启用开发者模式后需要重新执行该命令。
