### 二、修复的问题（按性质分类）

**A. 生产代码真 bug（SQLite 掩盖、真实 MySQL 必炸）**

1. `document` 模块 `Service.Create` / `Service.Update` **漏传 `Now`**（只有 `changeStatus` 传了）。
   仓储用它写 `audit_logs.created_at`、`idempotency_records.created_at`、`updated_at`；
   零值时间会被 MySQL 严格模式拒绝：
   `Error 1292: Incorrect datetime value '0000-00-00' for column 'created_at'`。
   SQLite 容忍零值日期，所以纯单测全绿、集成测试长期 SKIP，把这个漏洞藏到了现在。
   → 系统排查确认 settlement / reporting / organization / platform / finance 都正确传了 `Now`，
   **只有 document 有**。修复：Create/Update 补 `Now: s.now().UTC()`。

2. `platform` 模块 `ListGroups` 用 `Table("groups AS g")`。**`groups` 是 MySQL 8.0 保留字**
   （窗口函数的 `GROUPS` 帧单位），`Table()` 一旦带别名就走「原样 SQL」分支不做引号转义，
   真实 MySQL 直接 `Error 1064` 语法报错。SQLite 对保留字不敏感，单测照样过。
   → 修复：手写反引号 `Table("`groups` AS g")`。
   **但反过来有陷阱**：`loadAccessState` 里的 `Table("groups")`（不带别名）配 `First()` 时
   **绝不能手写反引号**——那会让 `Statement.Table` 落空，GORM 拼出 `ORDER BY `.`id`` 的语法错误。
   实测两种写法 SQL：
   - `Table("groups")` → ``FROM `groups` WHERE id = ? ORDER BY `groups`.`id` LIMIT ?`` ✅
   - `Table("`groups`")` → ``FROM `groups` WHERE id = ? ORDER BY `.`id` LIMIT ?`` ❌
   结论：不带别名交给 GORM；带别名且后续用 `Count`/`Scan`（不依赖 `Statement.Table`）才手写引号。

3. `platform.GetGroupDetail` 把 `[]OwnerCandidateData`（含嵌套结构体 `identity.UserSummary`
   字段 `User`）直接交给 `Scan`，GORM 把该字段当关联关系解析并报
   `invalid field found for struct ...'s field User: define a valid foreign key for relations`。
   → 修复：先用扁平临时行结构体接结果，再手工组装 DTO。

**B. 集成测试期望写错（从未执行过，写的时候就没对齐真实口径）**

   和「待补录客户 0.00（草稿）」两项，测试却只期望 1 项。
   → 修断言为 2 项并逐项校验名称 / 金额 / `DocumentCount`（0 元行有信息量：提醒补录定价）。

5. `document` 子账号月度汇总：测试期望「只看本人 1 张」，但该用例在第 6 步已给子账号授了
   `document.view_others`，到汇总时数据范围已放开到全组 3 张。

6. `finance` 撤销后重放幂等键：原步骤先 `fin-pay-5` 再登记 30000（额度占满 100000），
   之后又用 `fin-pay-1` 重放 30000 → 必然撞「累计金额超过单据总额」。
   而且若两步都成功会变成 4 笔付款，与同文件后文「组内付款共 3 笔」的断言自相矛盾。
   → 修正为「撤销 30000 → 直接用 `fin-pay-1` 重放补回」，一次同时验证**额度回收**与**幂等记录释放**
   （若幂等记录残留会返回首次结果 paid=30000 或报 `IDEMPOTENCY_KEY_REUSED`，断言都能抓住）；
   再用 `fin-pay-5`（0.01）验证占满后仍被拒。

7. `platform` 重复撤销邀请码：实现是**幂等静默成功**（`if status == revoked { return nil }`），

   该分支业务上不可达。
